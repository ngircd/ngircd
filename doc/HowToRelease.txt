I. Introduction
~~~~~~~~~~~~~~~

Creating a new ngIRCd release requires a few steps to follow: the source
tree must be in a releasable state (be up to date, include all required
patches, be tested on as many platforms as possible), a name for the new
release must be chosen, and all the files describing the release must be
updated accordingly.

Since ngIRCd release 13 (2009-12-25) we use "simple" release numbers for
major releases (e.g. "13", "17", "42", ...) introducing new features and
sub-releases for bug fixes only (e.g. "14.1", "22.3", ...).

When creating pre-releases or release candidates, please use the tilde ("~")
character to separate the "postfix" in the release number (e.g. "17~rc2"
or "123.4~rc6").

The release/version number of a build is automatically generated using the
GIT "describe" command, see git-describe(1). Therefore it is required that
a new release is tagged in the GIT tree and that the configure script is
up-to-date (e.g. using ./autogen.sh) before generating the archives!


II. How to prepare a new ngIRCd release?
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

a) The distribution archives are built in a container using an old GNU
   automake (see h), so no special autoconf/automake versions are required
   on the system you use for preparing the release.

b) Make sure the source tree is in a releasable state ;-)
    - Are all branches & patches merged? Check GitHub issues, pull requests
      and milestones!
    - Run as many tests as you can!
    - Is the AUTHORS.md file up to date? This command may be helpful:
      "( grep '>$' AUTHORS.md; git shortlog -se|cut -c8-|sed 's/^/- /' ) \
        | grep -Ev '(alex@barton.de|fw@strlen.de)' \
        | LC_ALL=de_DE.UTF-8 sort -u"

c) Update the files describing the new release, including its date:
    - ChangeLog
    - NEWS

d) Update the version numbers and dates in the following files:
    - contrib/de.barton.ngircd.metainfo.xml
    - contrib/ngircd.spec
    - man/ngircd.8.tmpl
    - man/ngircd.conf.5.tmpl

e) Generate a new Debian change log entry in the following file, e.g. using
   the Debian "dch" tool of the "devscripts" package:
    - contrib/Debian/changelog

f) Commit the above changes to GIT: "git add", "git commit"

g) Create a new signed GIT tag for the new release: "git tag -s".
   Please note that we don't use the tilde ("~") here, instead use a simple
   hyphen ("-") as delimiter: e.g. "rel-16" "rel-17-rc1", "rel-18-pre2", ...
   The tag must be an annotated one (which signed tags are), as "git
   describe" ignores lightweight tags when generating the version number.
   Don't change the tagged commit afterwards (e.g. by rebasing or amending
   it): if something still has to be fixed, delete the tag, fix it, and
   create a new tag -- before anything is pushed or distributed!

h) The ngIRCd distribution archives should still support "de-ANSI-fication"
   in the build environment. This was supported up to GNU automake 1.11, and
   Debian 12 "Bookworm" is the last Debian release providing it. Therefore it
   is best to use a container and the build script
   "contrib/build-dist-archives.sh" to build the three distribution archives
   (tar.gz, tar.Z, tar.xz) like this:

   podman run --rm -v "$PWD":/src debian:bookworm-slim \
     /src/contrib/build-dist-archives.sh

   The build runs in place and overwrites all generated files (./configure,
   Makefiles, ...) in the source tree. "make distcheck" builds and tests the
   archives, but doesn't notice files that are missing from them: therefore
   the script lists all files tracked by GIT that are not distributed at the
   end; make sure that only files like ".gitignore" show up there.

i) Sign the distribution archives using GnuPG: "gpg -b <archivefile>"

j) Push the release commit and the new tag to all GIT repositories, e.g.
   "git push <remote> master rel-<NN>". This triggers the GitHub workflows
   building and publishing the container images, check their results.

k) Upload and distribute the newly generated ngIRCd release archives
   and GnuPG signatures (to the website, its mirrors, and GitHub):
   publish a GitHub release for the new tag, with the release notes and
   all archives and signatures attached, and mark it as "latest" (unless it
   is a pre-release). Mention contributors using their GitHub "@" handles
   in the release notes, then GitHub lists them on the release page.

l) Update the ngIRCd website and its mirrors!

m) Write an announcement to the mailing list, Mastodon, ...

n) Close the GitHub issues and pull requests fixed by the release, and the
   milestone of the release, if any.

o) Relax :-)
